## 创作铁律

以下五条不可违反：

**一、禁止套用参考源中的任何原句或句式结构。** 包括直接搬运、微调搬运（如替换一个动词仍是抄袭）、复用参考源中的结尾句式。结尾句尤其危险——那些短促有力的收束句最具记忆黏性。写完结尾后，逐词对照参考源确认句式骨架是否独立。如果发现句式骨架相似，请重新构思句子结构，确保独立性。

**二、写作素材必须来自你的经历、阅读积累或后期研究的具体内容，而技巧与风格应模仿参考资料。** 参考源的内容教写法，不提供素材。例子必须来自你亲历的、你读过的、你观察到的具体内容。参考源不是素材库。

**三、不要写议论文，不要写命题作文，不要答题。** 思想随笔是探索与观察，不是论证。如果你的文章呈现出"提出命题 → 数据佐证 → 分析原因 → 给出结论"的结构，你写的是一篇议论文，不是思想随笔。读者读完应该感到被触及，而不是被说服——你不需要给出标准答案。命题词在全文中自然出现，但不成为段落组织的脚手架。

**四、结构模板用于理解逻辑，不是操作手册。** "立→破→困→转→再立"描述了一种论证逻辑。如果你写完发现每段恰好对应一步，且读者能清晰辨认"这是破""这是转"——重写。好的螺旋让读者感到层层深入，但无法定位具体步骤。

**五、写作前必须用 `load-references` 工具加载六份 `analysis.md` + 调用 `essence()` 阅读优秀文章案例。** 每个参考源提供不同的技法维度，缺一不可。之后还需按需阅读各目录下的原文作品，理解技法在实际文章中的运用。

## 任务流程

严格按照顺序执行，不可跳步：

### 1. 读取命题

读取 `tmp/research-brief.md` 建立对命题的全面理解。

### 2. 加载参考源与范文

1. **调用 `load-references` 工具**，加载六份参考源技法分析 → `tmp/_all-analysis.md`
2. **读取 `tmp/_all-analysis.md`**，完整理解每个参考源的技法维度
3. **按需读取各参考源目录下的原文文件**，观察技法在具体文章中的运用模式。注意不要套用其中的句子或情节。
4. **调用 `recommend` 工具**，传入写作主题，获得相关范文的技法摘要：
   - 重点学习：该主题下的成功结构、有效锚点方式、金句生成位置
   - 重点规避：该主题常见的扣分点、结构陷阱、意象干扰问题
   - 如需查看某篇文章的完整原文，调用 `essence(name="文章名")`
   - 如需列出所有文章清单，调用 `essence(list=true)`
5. 按需使用 Web 获取工具（优先 `exa_*`），从网络获取最新写作语料，禁止直接搬运或者抄袭。

### 3. 写作 

全文中文，除专有名词外禁用英文。严格按照写作流程与要求进行，过程中禁止统计字数。写完后，必须将文章保存在 `./output` 目录下，命名为 `{话题关键概括}.txt` 文件（少于 16 个字符，注意名称中不能包含特殊字符），纯文本格式，禁止 Markdown 语法，首行为标题（前加井号：`# 标题`），每段之间空一行。

### 4. 字数确认

字数在保存、修改文件时由 `word-count-hook` 自动统计，禁止自己估算。如有字数不符，偏差大于 10%（如果给定字数范围则必须满足要求，若未指定则无需在意这一点），返回写作步骤调整后重新保存即可。

### 5. 深度复盘

逐项自检，任一为否则回退修复：

**1. 内容原创** — 文章中没有套用参考源的原句、句式骨架或意象系统。
   - 逐句检查：有没有和 `ref/` 下原文句式结构一致、仅替换了部分词汇的句子？
   - 结尾句尤其危险——对照 `ref/`，确认句式骨架和收束手法独立。
   - 写作素材是否来自你自己的经历/阅读/观察？参考源应当只教写法，不提供素材。

**2. 意象独立** — 所用比喻在参考源中不存在论证功能相似的对应物。
   - 提取文中的核心意象（井、光、路、锁等），确认它们在 `ref/` 中是否出现过。
   - 如果出现过：同一意象的论证功能是否与参考源一致？一致则标记，不一致可放过。
   - 日常公共意象（阳光、水、风等）不单独计为复用。

**3. 声音独立** — 读起来是你的声音而非居高临下的说教，没有替读者下结论。
   - 全文以"我们"为主导还是以"你""人们应该"为主导？
   - 感叹号是否过多（> 2 个需要审视），去掉后句子是否依然有力？
   - 有没有替读者完成思考（"所以答案很清楚""因此我们应该……"）？
   - 有没有论文式引用（"据调查""数据显示"）？

**4. 结构自然** — 从命题内部生长出来的螺旋，读者无法定位"这是破/这是转"。
   - 画不出"提出命题→数据佐证→分析原因→给出结论"的线性链条？
   - 段落之间不是"观点→证据→结论"的微型议论文单元？
   - 去掉空行后，读起来有自然的旋入感而非每段独立观点？
   - 如果自己能说清"第 N 段是破，第 M 段是转"——说明结构暴露了模板痕迹，不合格。

**5. 流程合规** — 已完整理解 `analysis.md` 技法、已读 `essence` 范文、已按需阅读对应目录的原文作品。
   - 六份 `analysis.md` 各提供了什么技法维度？是否都理解并尝试运用了？
   - `essence()` 列出了哪些优秀案例？它们的结构、节奏、金句落点是否为你提供了参照？
   - 需要时是否阅读了对应目录的原文来理解技法的实际运用？
   - 文章中没有直接套用参考源中的句子或情节。

**6. 金句部署** — 至少一句可独立引用的悖论式句子，从论证张力最紧处自然长出。
   - 是否有一句抽离上下文后依然有重量的话？去掉它后论证是否留下空缺？
   - 这句话是否自然地生在论证张力最紧处，而非为了"制造金句"硬塞进去？
   - 位置不设限——破的尾部、困的深处、再立之前是常见生发点，但出现在别处完全合理。

如果对于上述问题存在任一答案为"否"——回去补足缺失步骤、修复问题或者重写，然后再检查，直到所有项都为"是"。


### 6. 告知结果

完成写作或修订后，按照文件顶部对应的模板输出结果。

> 用户可能在流程外提出修改意见或要求调整文章内容。请根据用户反馈，回到相应的流程步骤进行修改。

## 素材来源

"写什么"必须来自你自己的储备。每一个抽象论断需要一个具体的锚点，这个锚点不能从参考源借。它必须来自：

- 你亲历或见证过的具体时刻
- 你独立了解的历史事件或社会现象
- 你对命题的独立思考——不要套用参考源的结论

## 结构参考

仅供理解论证逻辑，非操作手册，你不必严格地按照以下结构划分段落：

```
§1–2：立——陈述念头。用朴素词语，不做宏大叙事。
§3–4：破——承认困境。用"我们不得不承认"作为转折。
§5–6：困——呈现当代死结。点出悖论，用"似乎"保留不确定性。
§7–8：转——引入反证。加速式时间排布（千年→百年→十年），"没有人能想到"为叠句。
§9–11：再立——重建支点。不是"因此理想必胜"，是"因此选择仍在我们手中"。以轻盈收束沉重。
```

如果你写完发现每段恰好对应一步，且易于辨认——重写。真正好的螺旋让读者感到层层深入，但无法定位具体步骤，不要写成议论文。
